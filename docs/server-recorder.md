title: Server Recorder
---

The Server Recorder is part of the [Inspector plugin](./getting-started.md#appium-plugin).
It records what any client does in an Appium session - test code, an
AI agent working through an MCP server, or the Inspector itself - and turns
it into locators and test code.

Unlike the [Recorder tab](./session-inspector/recorder.md), which records only
the actions performed in the Inspector, the Server Recorder runs inside the
Appium server and sees every command of the sessions it records, whichever
client sends them.

!!! note

    The Server Recorder is only available with the Inspector plugin. The
    Appium server must be started with the plugin activated:

    ```bash
    appium --use-plugins=inspector
    ```

## Starting a Recording

Sessions are not recorded by default: sessions that are not recorded pass
through the plugin unchanged. A recording can be started in several ways:

- From the [Recordings tab](./session-builder/recordings.md) of the Session
  Builder, or the [Recorder tab](./session-inspector/recorder.md) of an
  attached session, using the **Record** button
- From any client, by running the `inspector: startRecording` extension
  command (see [Extension Commands](#extension-commands))
- When the session is created, by setting the `appium:inspectorRecord`
  capability to `true`
- For every session on the server, by starting Appium with the
  `APPIUM_RECORDER=all` environment variable

A recording can be paused and resumed to leave steps out. Stopping a recording
is final: it is saved, and the same session cannot be recorded again. Ending
the session also stops and saves its recording.

## Extension Commands

The recorder is controlled with the following extension commands, which any
Appium client can run with its `executeScript` method. These commands are
never recorded themselves.

- `inspector: startRecording`: start recording the session
- `inspector: pauseRecording`: stop adding steps until resumed
- `inspector: resumeRecording`: continue adding steps
- `inspector: clearRecording`: drop the steps recorded so far
- `inspector: stopRecording`: finish the recording and save it
- `inspector: getRecording`: get the recording (optional parameters
  `format`, `boilerplate` and `includeSteps`, see below)

`inspector: getRecording` returns the recording status and its `locators.md`
summary. With `format`, it also returns test code generated by the same code
generators as the Recorder tab. Supported formats are `python`, `java`
(JUnit 4), `junit5`, `wdio`, `oxygen`, `ruby`, `csharp` and `robot`. Set
`boilerplate` to `true` to include the session setup code, and `includeSteps`
to `true` to also get the raw recorded steps.

For example, in Python:

```python
driver.execute_script('inspector: startRecording')
# ... perform the scenario ...
recording = driver.execute_script(
    'inspector: getRecording', {'format': 'python'}
)
print(recording['code'])
driver.execute_script('inspector: stopRecording')
```

!!! tip

    AI agents can control the recorder through any MCP server that can run
    driver extension commands, and receive the generated test code directly
    from `inspector: getRecording`.

## What Is Recorded

Only commands that succeed are recorded, and only those that act on the
application or read from it:

- Element actions: click, clear and typing (`setValue`)
- Element reads, such as `getText` or `getAttribute`, which become
  verification comments in the generated code
- `executeScript` calls, including element references in their arguments
- Navigation commands and W3C actions

Element finds are not recorded as steps: each action is linked to the
locator that found its element. Finds whose element is never used, page source
and screenshot requests, and other exploration do not appear in the recording.

Script calls that only read and involve no element (for example
`windows: getWindows`) are kept in the recording with their result, but are
shown commented out in the generated code.

### Locator Suggestions

Before the first action on an element that was found with a locator other
than `accessibility id` (or that has no recorded locator), the recorder reads
the page source, finds the element in it, and replaces the locator in the
generated code with the best unique locator suggested by the Inspector's
locator generation. The generated code notes the locator that was originally
used. Each element is checked once, and the page source is reused until a
command may have changed the application state.

### Password Fields

Text typed into fields that the driver reports as password fields
(`IsPassword` or `password` attribute) is replaced with `{{PASSWORD}}`.

## Saved Recordings

When a recording is stopped, it is saved into its own folder inside the
recordings folder (by default `appium-recordings` in the user's home
directory). Each folder contains:

- `steps.json`: the recorded steps and session details
- `actions.json`: the steps as Recorder tab actions, used for code generation
- `locators.md`: one line per step with its locator, for writing tests by hand

Saved recordings are listed in the
[Recordings tab](./session-builder/recordings.md), also after restarting the
Appium server, and can be deleted from there.

## Configuration

The recorder is configured with environment variables set when starting the
Appium server:

- `APPIUM_RECORDER` (default `on`): `on` records sessions on request,
  `all` records every session, and `off` disables the recorder
- `APPIUM_RECORDER_DIR` (default `~/appium-recordings`): the folder where
  recordings are saved
- `APPIUM_RECORDER_LOCATORS` (default `on`): `off` keeps the locators that
  the client sent, without reading the page source for suggestions

## HTTP API

The Recordings tab uses the following routes, which are served by the Appium
server alongside the Inspector:

- `GET /inspector/api/recordings`: list live sessions and recordings
- `GET /inspector/api/recordings/:sessionId`: get a recording
- `GET /inspector/api/recordings/:sessionId/locators.md`: get the
  recording's `locators.md`
- `POST /inspector/api/recordings/:sessionId/start`: start recording a live
  session
- `POST /inspector/api/recordings/:sessionId/pause` and `.../resume`: pause
  or resume a recording
- `POST /inspector/api/recordings/:sessionId/stop`: stop and save a
  recording
- `DELETE /inspector/api/recordings/:sessionId`: delete a finished recording
  and its saved files

!!! warning

    Like the Appium server itself, these routes have no authentication.
    Recordings can contain the text typed during a session, so do not expose
    an Appium server with the Inspector plugin to untrusted networks.
